# إعداد الدفع التلقائي بـ USDT — Wakeel

## ما تم تنفيذه

أُضيف دفع تلقائي مباشر بعملة مستقرة على **BNB Smart Chain Mainnet (BSC / BEP-20، Chain ID 56)**. ينشئ الموقع طلبًا بمبلغ مميز وفريد بفارق أقل من `0.01 USDT` كي يستطيع ربط التحويل بالفاتورة على عنوان الاستلام المشترك. يعرض الموقع عنوان الاستلام ورمز QR يتضمن عقد الرمز والمبلغ الدقيق في المحافظ المتوافقة مع EIP-681؛ أرسل المبلغ الظاهر بالضبط، لا السعر الأساسي وحده. يراقب Cloudflare Worker التحويلات تلقائيًا كل خمس دقائق عبر Cron Trigger، ويضيف الرصيد بعد 15 تأكيدًا دون مراجعة إدارية، حتى إذا لم يُدخل المستخدم Tx Hash. يمكن لصق Tx Hash اختياريًا في صفحة الدفع لتسريع التحقق.

العنوان الذي أُدرج في إعدادات النشر:

`0x8575DB82A480428Ef0d9eB9b9a62de3453303Fc9`

## تنبيه مهم حول الرمز والشبكة

التنفيذ الحالي يتحقق من عقد الرمز التالي على BSC:

`0x55d398326f99059fF775485246999027B3197955`

يعرض BscScan هذا العقد باسم **Binance-Peg BSC-USD** وبـ 18 منزلة عشرية؛ كثير من المحافظ تعرضه باسم USDT. لا تخلطه مع USDT على Ethereum (ERC-20) أو Tron (TRC-20)، ولا ترسل رمزًا من عقد آخر. راجع صفحة العقد في BscScan قبل الإيداع: https://bscscan.com/token/0x55d398326f99059fF775485246999027B3197955 . لا أستطيع استنتاج الشبكة التي يتحكم بها عنوان الاستلام من شكل `0x` وحده؛ تم اعتماد BSC BEP-20 لأن تدفق الدفع السابق كان يستخدم `usdtbsc`.

## النشر

إذا كان المشروع منشورًا سابقًا، وكانت القيم التالية محفوظة كـ Cloudflare Worker secrets وفق دليل الإصدار القديم، فاحذفها مرة واحدة حتى يستطيع Wrangler استخدام القيم العامة الموجودة في `wrangler.toml` بدلًا منها:

```bash
npx wrangler secret delete TRUST_WALLET_ADDRESS
npx wrangler secret delete TRUST_WALLET_NETWORK
npx wrangler secret delete TRUST_WALLET_TOKEN
```

نفّذ أوامر الحذف فقط للأسرار الموجودة حاليًا؛ لا حاجة إلى حذف شيء في نشر جديد. الفواتير المباشرة التي أُنشئت قبل تطبيق ترحيل `0005_bsc_payment_scan_cursor.sql` لا تحتوي على حدّ الكتلة الجديد؛ أنشئ فاتورة جديدة لهذه النسخة ولا ترسل إلى فاتورة قديمة.

1. افتح `wrangler.toml` وتأكد من `TRUST_WALLET_ADDRESS` وأنه عنوان محفظتك أنت.
2. قيمة `TRUST_WALLET_NETWORK` هي `BSC Mainnet (BEP20)`، وقيمة `TRUST_WALLET_TOKEN` توضّح عقد الرمز المعتمد.
3. `BSC_RPC_URL` مضبوط افتراضيًا على `https://bsc-dataseed.bnbchain.org`، ويمكن استبداله بعنوان RPC موثوق لشبكة BSC mainnet.
4. طبّق الترحيلات على D1 البعيد، ثم ابنِ الواجهة وانشر:

```bash
npm run db:migrate:remote
npm run typecheck
npm test
npm run web:build
npm run deploy
```

لا تُضف المفتاح الخاص أو عبارة الاسترداد إلى المشروع أو Cloudflare. لا يحتاج هذا المسار إلى مفتاح BscScan ولا مفتاح مدفوع؛ يستخدم JSON-RPC عامًا، لكن قد تفرض نقاط RPC العامة حدود استخدام أو انقطاعات مؤقتة.

## دورة الدفع

1. ينشئ الموقع الفاتورة ويأخذ لقطة من أحدث رقم كتلة على BSC؛ لا يسمح بربط تحويل أُدرج في كتلة أقدم من الفاتورة.
2. يرسل المستخدم الرمز المحدد إلى عنوان الاستلام على BSC فقط، مع إرسال المبلغ الدقيق الظاهر (يشمل الفرق التعريفي الأقل من `0.01 USDT`) وترك ما يكفي من BNB لرسوم الشبكة.
3. كل خمس دقائق، يفحص Cron Trigger سجلات `Transfer` من عقد الرمز المحدد وإلى عنوان الاستلام، ويتجاهل الكتل التي لم تصل إلى 15 تأكيدًا.
4. يطابق النظام التحويل مع مبلغ فاتورة فريد، ويتأكد أن كتلة التحويل أحدث من كتلة إنشاء الفاتورة، ويمنع إعادة استخدام Tx Hash أو مبلغ فاتورة سبق تخصيصه. بعد المطابقة يضيف الرصيد مرة واحدة باستخدام آلية D1 الذرية.
5. يمكن للمستخدم لصق Tx Hash في واجهة الدفع للتحقق الفوري؛ هذا اختياري وليس شرطًا. لا تُقبل صور الشاشة أو ادعاءات الواجهة دليلًا على الدفع.

لا يستطيع هذا الأسلوب التعرّف إلى أي تحويل بمبلغ عشوائي لا يطابق الفاتورة بدقة، ولا يربط تحويلًا أُرسل قبل إنشاء الفاتورة بها. لا ترسل مبلغًا مختلفًا ولا تجمع أكثر من فاتورة في معاملة واحدة إلى عنوان الاستلام المشترك.

## الاختبارات والحدود

أُضيفت اختبارات لمطابقة عقد الرمز والمستلم والمبلغ وسلسلة BSC وعدد التأكيدات، وكذلك ترحيل قاعدة بيانات المؤشر. لم تُختبر دفعة مالية حقيقية ولا تم نشر المشروع من هذه البيئة؛ نفّذ `npm test` و`npm run typecheck` و`npm run web:build` قبل الاعتماد الإنتاجي. حدّث قاعدة بيانات D1 البعيدة قبل النشر، وتأكد من ظهور Cron Trigger في إعدادات Cloudflare Worker، ثم جرّب دفعة صغيرة من محفظة تملكها أولًا.
